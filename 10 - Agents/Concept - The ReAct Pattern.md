> **One-paragraph hook:** Ask an LLM to reason its way to an answer and it will confidently make facts up; ask it to just call tools with no reasoning and it flails without a plan. ReAct fixes both by making the model alternate — think a little, act a little, read what actually happened, repeat — and that single interleaving is the ancestor of essentially every agent loop running in production today.

## The mechanism

ReAct (Yao et al. 2022, *ReAct: Synergizing Reasoning and Acting in Language Models*) has the model generate a single stream of text broken into repeating triples:

```
Thought: <reasoning about what to do next, given everything so far>
Action: <a tool call — search[query], lookup[term], calculator[expr], ...>
Observation: <the real result returned by executing that action>
```

The loop repeats until the model emits a final answer instead of another action. The mechanism works because the two failure modes it targets are complementary. Chain-of-thought-only prompting (see [[Concept - Chain-of-Thought and Why It Works]]) lets the model reason step by step, but every "fact" it invokes along the way is generated, not retrieved — it hallucinates plausible-sounding intermediate facts and the chain drifts further from ground truth with every step. Act-only prompting (no Thought lines, just Action → Observation) grounds every step in a real observation, but the model has no scratchpad to track *why* it's doing what it's doing, so it loses the plot on multi-step tasks. Interleaving both means the Thought decomposes the task and tracks progress against the goal, and the Action grounds the next step in something real instead of something remembered wrong. Each Observation then becomes the input to the *next* Thought, so grounding compounds instead of decaying.

## In practice

The original paper's empirical contrast is the paper's real contribution: on HotpotQA and FEVER (multi-hop QA and fact verification), ReAct beat CoT-only on hallucination rate because every intermediate claim was checkable against a real Wikipedia lookup. On ALFWorld and WebShop (interactive environments — a simulated household and a shopping site), ReAct beat act-only because the Thought traces let the model plan around a bad observation instead of just reacting to it one step behind.

The original implementation is now a museum piece in one specific way: it used a handful of hand-written few-shot exemplars with `Thought:`/`Action:`/`Observation:` as literal strings, and a text parser scraped the Action line to figure out what to call. That parser was brittle — a stray colon or a slightly reformatted action string broke the whole loop. Modern practice keeps the *interleaving* and throws away the *text parsing*: the Thought is still free text (often the model's native reasoning/thinking output), but the Action is emitted as a native structured tool call via [[Concept - Tool Use and Function Calling]] instead of a string the harness has to regex out. [[Deep Dive - The Agent Loop]] traces this evolution — text-parsed ReAct (2022) → native function calling → parallel tool calls → interleaved extended-thinking and tool use — as successive removals of one parsing-failure class at a time. [[Snippet - A Minimal ReAct Loop]] is the ~50-line runnable version of this modern form.

## Failure modes

- **Repeating the same failing action.** The model's Thought rationalizes *why* the action should work rather than diagnosing why the last identical attempt didn't — reasoning becomes post-hoc justification instead of diagnosis. Detection: log consecutive identical tool calls; a repeat count above 2-3 is a strong loop signal.
- **Oscillating between two states.** The agent alternates between two actions that undo each other (open then close, search A then search B then back to A) without making net progress. Detection: hash the (action, observation) pairs and watch for cycles, not just exact repeats.
- **Thoughts that entrench rather than diagnose.** Because the Thought is generated by the same model that just took a wrong action, it's a double-edged scratchpad: cheap and useful when it's honestly diagnosing an observation, but equally capable of rationalizing a bad path as still-correct. This is the same self-correction ceiling described in [[Concept - Reflection and Self-Correction]] — reasoning about your own error without an external signal doesn't reliably fix it.

## The non-obvious

The thought tokens are not free reasoning capacity you get for nothing — they're a liability exactly where they're an asset. The property that makes ReAct work (giving the model a place to reason about what to do next) is the same property that lets a stuck agent talk itself into staying stuck, because the model that generated the bad plan is also the model grading whether the plan still makes sense. This is why production loop designs pair ReAct's interleaving with an external check whenever one is available — a test suite, a compiler, a retrieved fact — rather than trusting the Thought alone to self-correct. [[Concept - Reflection and Self-Correction]] extends this idea across episodes: Reflexion adds a verbal-feedback memory the agent writes after a failed episode and reads before the next attempt, which is ReAct's within-episode grounding pushed out to inter-episode learning.
